## Этап 1:  Сборщик конфигураций

Создать скрипт, который будет ходить по роутерам.

1. **Написание скрипта сбора (`collector.py`):**
    
    - Используйте библиотеку `netmiko` (она отлично работает с Huawei VRP).
        
    - Определите словарь с параметрами подключения к маршрутизаторам (IP, логин, пароль/SSH-ключ).
        
    - Составьте список команд `display current-configuration ...`, которые нужно собирать.
        
2. **Интеграция с базой данных (SQLite):**
    
    - Напишите функцию создания таблиц в SQLite (`router_configs.db`). Структура: `id, scan_date, router_name, command, raw_output`.
        
    - Доработайте скрипт сбора: после получения вывода от роутера, скрипт должен вставлять эти данные в БД вместе с текущей меткой времени (`scan_date`).
        
3. **Тестирование и автоматизация (Cron):**
    
    - Запустите скрипт вручную, убедитесь, что он успешно подключается к Huawei, забирает данные и кладет их в SQLite.
        
    - Настройте планировщик задач `cron` в Linux (например, `crontab -e`), чтобы `collector.py` запускался раз в сутки (например, в 03:00 ночи).
        

### Этап 3: Разработка поискового API (Backend - API)

Теперь нужен интерфейс, который будет отвечать на запросы фронтенда.

1. **Создание веб-сервера (FastAPI):**
    
    - Создайте файл `api.py`.
        
    - Инициализируйте базовое приложение FastAPI.
        
2. **Написание логики поиска:**
    
    - Создайте функцию, которая делает запрос в SQLite: находит самую свежую `scan_date` (последний бэкап).
        
    - Выгружает все записи (`raw_output`) для этой даты.
        
    - Выполняет поиск подстроки (например, `"123"`) построчно внутри `raw_output`.
        
3. **Создание эндпоинта (Endpoint):**
    
    - Сделайте маршрут, например, `GET /search?query=123`.
        
    - Эндпоинт должен вызывать логику поиска и возвращать JSON со структурированным ответом (Имя роутера -> Имя команды -> Найденные строки).
        
    - Настройте CORS (Cross-Origin Resource Sharing) в FastAPI, чтобы фронтенд мог делать запросы к бэкенду.
        

### Этап 4: Разработка веб-интерфейса (Frontend)

Делаем интерфейс для инженеров.

1. **Инициализация проекта:**
    
    - Создайте базовое React-приложение (используя `Vite` или `Create React App`).
        
    - Установите Tailwind CSS для быстрой и красивой стилизации (как в прототипе).
        
    - Установите иконки (например, `lucide-react`).
        
2. **Верстка интерфейса:**
    
    - Создайте строку поиска и кнопку "Найти".
        
    - Сделайте блоки для отображения результатов (карточки маршрутизаторов).
        
3. **Интеграция с API:**
    
    - Напишите функцию отправки запроса (через `fetch` или `axios`) к вашему FastAPI эндпоинту (`GET /search?query={поисковый_запрос}`).
        
    - Обработайте состояние загрузки (чтобы показывать спиннер, пока бэкенд ищет данные).
        
    - Отрисуйте полученный JSON в виде читаемого дерева (Маршрутизатор -> Команда -> Строка), подсвечивая искомый текст желтым маркером.
        

### Этап 5: Развертывание (Деплой) и тестирование

Переносим все в "продакшен" (на выделенный сервер).

1. **Сборка фронтенда:**
    
    - Выполните сборку React-приложения (`npm run build`). Вы получите статические файлы (HTML, CSS, JS).
        
2. **Настройка веб-сервера (Nginx):**
    
    - Установите Nginx на сервере.
        
    - Настройте его на раздачу статических файлов фронтенда.
        
    - Настройте обратное проксирование (Reverse Proxy) в Nginx, чтобы запросы к `/api` перенаправлялись на ваш FastAPI сервер, работающий локально.
        
3. **Запуск бэкенда как сервиса:**
    
    - Настройте Systemd unit (службу Linux) для запуска FastAPI (через `uvicorn` или `gunicorn`), чтобы он работал в фоне и автоматически перезапускался при перезагрузке сервера.
        
4. **Финальное тестирование:**
    
    - Зайдите в веб-интерфейс.
        
    - Сделайте тестовые запросы (например, найдите существующую AS).
        
    - Проверьте, что результаты отображаются корректно и поиск работает по самым свежим данным.
