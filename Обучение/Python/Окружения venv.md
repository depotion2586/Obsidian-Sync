**Virtual Envierment** - это окружение, в котором своя версия Python, у которой свой набор библиотек и надстроек, которые могут отличаться от тех, которые установлены непосредственно на машине. Это необходимо для совместимости и легковесности. Не засорять основной Python ненужными библиотеками, предотвратить конфликты версий разных приложений. 

### Создание и эксплуатация виртуальных сред
`python -m venv [/opt/test]` - команда создания виртуальной среды в папке с именем [test]
`source /opt/test/bin/activate` - переход к работе виртуальной среде `test`. После этого все команды в терминале будут выполняться в рамках этой среды.
	**Примечание(1):** после перехода в определенную виртуальную среду внутри нее для эксплуатации используется утилита `pip`
	**Примечание(2):** последующие команды можно выполняить, не находясь внутри окружения, но тогда нужно прописать путь до утилиты `pip`, находящейся в конкретном окружении. Находится тут: */opt/test-env/bin/pip*. Либо заранее войти в окружение 
`pip install TEST` - установка библиотеки `TEST`
`pip freeze > requirements.txt` - перенести все необходимые библиотеки для проекта в файл `requirements.txt`
`pip install -r requirements.txt` - установить все библиотеки, описанные в файле `requirements.txt`
`pip list` - просмотр установленных пакетов
`diactivate` - выйти из окружения

**Примечание(3):** `Shebang` - делает так, чтобы скрипт запускался короткой командой, не прописывая полный путь до него. Что бы это сделать необходимо: 
1. Прописать в самом начале скрипта следующее:
	`#!/opt/test-env/bin/python3` 
2. После этого сделать скрипт исполняемым (по умолчанию скрипты для системы это просто текстовые файлы)
	`chmod +x .../test.py` - система поменяет атрибуты файла, сделав его исполняемым
3. Теперь можно запускать `test.py` командой
	`./test.py`
