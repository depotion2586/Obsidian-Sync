 **Определение** — Loopback интерфейс является виртуальной сетевой картой. Применяется, когда разным приложениям нужно общаться на одном физическом устройстве. В таком случае им нет необходимости выходить в интернет. Через подобный интерфейс сделать общение разных приложений проще и безопасней. Являются более простым аналогом [[Network NameSpaces (netns)]] без присущей последним изоляции.
### Примеры использования

1. Создание сайта и просмотр его локально на машине, перейдя на сайт:
	- `http//:localhost:8000` или `http//:127.0.0.1:8000`
	**Примечание:** Таким образом код и браузер общаются в рамках одной машины, используя локальный адрес для взаимодействия.
2. Взаимодействие микросервисов, находящихся физически на одном сервере
3. Создание нескольких LoopBack интерфейсов:
		Создавать несколько lo интерфейсов может быть необходимо в случае, когда:
	-    Два и более приложений используют один порт:
		На lo создается необходимое количество IP -> для каждого приложения будет свой IP и свой порт не нем.
	-    Использование во внутренней сети BGP:
		Иногда сервера во внутренней сети общаются по BGP. Если кабель рвется - BGP интерфейс падает. Что бы этого избежать IP адрес вешают на dummy. Так интерфейс никогда не будет падать а трафик на сервер может попадать через любой подключенный кабель.
	**Примечание:** LoopBack интерфейс всегда один, но у него используется подсеть 127.0.0.0/8, что дает более 16 млн. адресов. Можно добавлять на один lo интерфейс  множество IP адресов, где каждый использует свой порт.  Можно также создавать тип **dummy** — это тоже самое что и другой lo интерфейс, создается в случае, когда нужно контролировать lo интерфейсы, включать и отключать их.  

### Взаимодействие интерфейсов

Пакеты между разными dummy или же IP в рамках одного lo могут взаимодействовать. Их маршрутизирует ядро, которое основывается на скрытой таблице маршрутизации `local`, которую можно посмотреть командой `ip route show table local`. Обычная маршрутизация не применяется так как это виртуальный интерфейс. При этом маршруты в таблице `local` обновляются каждый раз, когда создается или обновляется `lo/dummy` интерфейс. Ядро само добавляет новый или обновленный IP `lo/dummy`, понимая таким образом что обращение на эти IP значит обращения системы самой к себе. Кстати благодаря этой же таблице `local` разные `lo/dummy` могут общаться и между собой. 
	**Примечание (1):** пакеты, пришедшие на lo интерфейс **НИКОГДА** не попадут в глобальную сеть напрямую. Данный интерфейс изначально создан для общения программ и приложений в рамках одной машины, а не за ее пределами.  
	**Примечание (2):** маршруты можно добавлять вручную в таблицу маршрутизации `local`, используя [[#^ec2618|эти команды]]. 
### Как создавать, управлять loopback интерфейсами: 

**Работа с адресами на lo:**
`ip addr show lo` — Посмотреть статус lo
`ip addr add 127.X.X.X/X dev lo` — Добавить дополнительный IP-адрес на lo (алиас)
`ip addr del 127.X.X.X/X dev lo` — Удалить IP-адрес с lo
`ip route add local X.X.X.X dev lo table local` — Создание маршрута в таблице `local`:
`ip route delete local X.X.X.X dev lo table local` — Удаление маршрута в таблице `local`: ^ec2618

**Работа с dummy интерфейсами**:
`modprobe dummy` — Загрузить модуль ядра для dummy интерфейса
`TEST``ip link add name TEST type dummy` — Создать новый интерфейс с именем 
`ip addr add 1.1.1.1/32 dev dummy` — Назначить ему IP адрес
`ip link set TEST up` — Включить интерфейс 
`ip link delete TEST` — Удалить dummy интерфейса
