Простым языком - являются виртуальными проводами, которые соединяют виртуальные интерфейсы, позволяют им общаться друг с другом и выходить в интернет. Подобные провода всегда создаются парами:
	один конец в один конечный интерфейс, другой — в другой. Сочетается с [[Network NameSpaces (netns)]] 
### Пример использования

Подключение контейнеров к сети, контейнеры, создаваемые докером неизбежно создаются на отдельных, изолированных сетевых картах NameSpaces, которые требуются в "проводе" для выхода во внешнюю сеть, или взаимодействия с другими контейнерами.
	**Примечание:** Внутри контейнера в идеале переименовывать провод veth в eth0, привычный для всех программ и приложений.

### Диагностика
В Linux интерфейс можно переименовать как угодно. Системы контейнеризации (и скрипты администраторов) часто закидывают один конец Veth в Namespace и сразу переименовывают его в классический `eth0`, чтобы программам внутри было привычно работать. Что бы доказать причастность `veth` с одной стороны, и `veth` переименованного с другой необходимо:
	Выполнить вывод в стандартной оболочке команды `ip link` и смотреть на вывод `veth` интерфейса: *`4: veth-pm@if3: ... link-netns test-lab`*
		В выводе `4` - порядковый номер интерфейса в стандарт обол. `@if3` - порядковый номер интерфейса второго `veth`, связность с которым мы и ищем. `ink-netns test-lab` - то, где искомый `veth` находится. 
	Перейдя в контейнер `test-lab` посмотреть все доступные интерфейсы. Тот, у которого будет порядковый номер `3` и будет являться парой для `veth`
### Как создавать, управлять veth
`ip link add VETH_HOST type veth peer name VETH_QUEST` - cоздать пару veth с названиями `VETH_HOST` и `VETH_QUEST` в текущем контейнере/сетевой карте по умолчанию
`ip link set VETH_QUEST netns NS1` - перекинуть конец `VETH_QUEST` в контейнер `NS1`
	`ip addr add x.x.x.x/x dev VETH_HOST` - назначить IP концу `VETH_HOST` для последующей маршрутизации в контейнер `NS1`
	`ip link set VETH_HOST up` - включение виртуального порта `VETH_HOST`
		**Примечание(1):** Точно также необходимо настроить `VETH_QUEST` внутри контейнера `NS1`
`ip link del VETH_HOST` - удалить конец `VETH_HOS`. Конец, находящийся внутри контейнера `NS1` - `VETH_QUEST` удалится автоматически.
